## 📖 О проекте

**Prognoz Weather Bot** решает проблему получения понятного, подробного и локализованного прогноза погоды прямо в мессенджере Telegram. 

В отличие от стандартных погодных ботов, которые ориентированы исключительно на крупные города и часто не находят небольшие населённые пункты, данный проект оснащён умным алгоритмом геокодинга. Бот понимает названия сёл, деревень, посёлков (пгт), хуторов, станиц, умеет отсекать статусные префиксы, корректно обрабатывает букву «ё» и позволяет выбрать нужную локацию среди одноимённых вариантов с учётом региона и страны.

Вся навигация построена на интуитивном кнопочном интерфейсе (Inline Keyboards): пользователь может в один клик переключаться между днями, изучать сводку с шагом в 3 часа или раскрывать почасовой прогноз для любого периода суток (ночь, утро, день, вечер).

## ✨ Возможности

- **Мультиязычность и локализация (RU / EN)**:
  - При первом запуске бота пользователю предлагается выбрать предпочтительный язык интерфейса (`🇷🇺 Русский` или `🇬🇧 English`).
  - Полная адаптация всех текстовых сообщений, названий месяцев, дней, подсказок по поиску, описаний погодных условий (коды WMO), направлений ветра (16 румбов) и единиц измерения под выбранный язык.
  - Возможность смены языка в любой момент через главное меню `[ 🌐 Язык / Language ]` или команду `/lang` (`/language`).
  - Передача параметра языка в Open-Meteo Geocoding API (`language="ru"` / `"en"`) для отображения названий найденных городов и стран на выбранном языке.
- **Умный поиск населённых пунктов**:
  - Распознавание любых типов поселений: города, сёла, деревни, посёлки городского типа (пгт), станицы, хутора, аулы, слободы и дачные посёлки.
  - Автоматическая очистка статусных приставок: `д.`, `с.`, `п.`, `г.`, `пгт`, `хутор`, `деревня`, `село` и др.
  - Поиск с уточнением региона через запятую, в скобках или слитным текстом (например: `Константиново, Рязанская область` или `Шерегеш (Кемеровская обл.)`).
  - Автоматическая обработка чередования букв **«е» / «ё»** при поиске.
  - Интерактивный выбор через inline-кнопки при обнаружении нескольких одноимённых мест с приоритезацией стран СНГ и сортировкой по численности населения.
- **Прогноз на 4 дня с учётом часовых поясов**:
  - `🌅 Вчера`: фактическая архивная погода за прошедший день.
  - `☀️ Сегодня`: прогноз на текущие сутки.
  - `🌇 Завтра`: прогноз на следующий день.
  - `📅 Послезавтра`: прогноз на два дня вперёд.
  - Определение локального часового пояса места (`timezone`) через стандартную библиотеку `zoneinfo`.
- **Два уровня детализации прогноза (Mobile-First)**:
  - **Суточная сводка**: компактная однострочная шапка (`📍 Город · Дата`), крупная температура со статусом, ощущаемая температура в скобках, округление до целых градусов, объединённые строки осадков и ветра.
  - **Почасовой прогноз**: оптимизирован для узких экранов смартфонов (320–375px), строго 1 строка на каждый час/интервал без переносов текста, моноширинное время `<code>00:00</code>`, температура целыми градусами, компактный вывод ветра и осадков без визуального шума.
- **Фактическая погода за прошлые сутки**:
  - Интеграция с архивом погоды Open-Meteo Historical API для просмотра фактических данных за вчерашний день.
- **Кэширование и производительность**:
  - Встроенный in-memory кэш погодных данных с временем жизни (TTL) 5 минут.
  - Кнопка `[ 🔄 Обновить ]` для принудительного сброса кэша и получения самых свежих данных.
  - Бесшовное редактирование сообщений в Telegram без создания лишнего спама в чате.
  - Настройка `trust_env=False` в HTTP-клиенте для изоляции от некорректных системных прокси.
- **Хранение данных пользователей**:
  - Персистентное сохранение выбранного места, координат, таймзоны и языка пользователя в SQLite через асинхронный драйвер `aiosqlite`.
- **Команды `/pogoda`, `/weather` и `/lang`**:
  - Быстрый вызов бота по команде `/pogoda` (или `/weather`) без необходимости использовать `/start` в общих чатах.
  - Мгновенный показ погоды на сегодня, если у пользователя уже сохранён город.
  - Поддержка аргумента с городом прямо в команде: `/pogoda Москва`, `/weather London`, `/pogoda пгт Шерегеш`.
  - Команда `/lang` (`/language`) для быстрого переключения языка интерфейса в один клик.
  - Защита групповых чатов от спама и перехвата сообщений: FSM-состояние не вешается на общий чат, пользователю предлагается понятная подсказка с синтаксисом.
  - Автоматическая регистрация команд в меню Telegram (`set_my_commands`) для удобных подсказок при вводе `/`.
- **Надёжная обработка ошибок и логирование**:
  - Вывод информационных логов в консоль и сохранение стектрейсов ошибок в файл `logs/errors.log`.

## 🚀 Установка

### Требования

- **Python 3.12** или выше
- **Git**
- Установленный **Docker** и **Docker Compose** (при развёртывании в контейнере)
- Токен Telegram-бота (получается у [@BotFather](https://t.me/BotFather))

### 1. Клонирование репозитория

```bash
git clone https://github.com/pi1zilo/tg-bot-prognoz.git
cd tg-bot-prognoz
```

### 2. Создание виртуального окружения и установка зависимостей

**На Linux / macOS:**
```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

**На Windows (PowerShell):**
```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
```

### 3. Настройка переменных окружения

Создайте файл `.env` в корневой директории проекта, скопировав шаблон из `.env.example`:

**На Linux / macOS:**
```bash
cp .env.example .env
```

**На Windows (PowerShell):**
```powershell
Copy-Item .env.example .env
```

Откройте файл `.env` в текстовом редакторе и укажите ваш токен:

```env
BOT_TOKEN=1234567890:ABCdefGHIjklMNOpqrSTUvwxYZ_example
DATABASE_PATH=weather_bot.db
```

## ⚙️ Конфигурация

Параметры приложения настраиваются через переменные окружения в файле `.env`:

| Переменная | Обязательность | По умолчанию | Описание |
|---|:---:|---|---|
| `BOT_TOKEN` | **Да** | — | Секретный токен Telegram-бота, выданный [@BotFather](https://t.me/BotFather). Без него бот завершает работу с кодом 1. |
| `DATABASE_PATH` | Нет | `weather_bot.db` | Имя или путь к файлу базы данных SQLite. Если указан относительный путь без префикса папки, файл автоматически сохраняется в директорию `data/weather_bot.db`. |

Каталоги `data/` (для БД) и `logs/` (для логов ошибок) автоматически создаются приложением при старте, если они ещё не существуют на диске.

## 🏃 Запуск

### Локальный запуск

Убедитесь, что виртуальное окружение активировано и файл `.env` заполнен:

```bash
python main.py
```

При успешном запуске в консоли отобразится:
```text
[HH:MM:SS] [INFO]: Бот запущен и ожидает сообщения...
```

Остановка бота выполняется сочетанием клавиш `Ctrl + C`.

---

### Запуск через Docker

Проект содержит готовый `Dockerfile` и манифест `docker-compose.yml`. Бот работает в режиме Polling, поэтому открытие внешних входящих портов не требуется.

1. **Запуск сервиса в фоновом режиме**:
   ```bash
   docker compose up -d --build
   ```

2. **Просмотр логов контейнера в реальном времени**:
   ```bash
   docker compose logs -f
   ```

3. **Остановка сервиса**:
   ```bash
   docker compose down
   ```

База данных SQLite сохраняется внутри именованного Docker-тома `bot_data` (путь в контейнере: `/app/data`), что гарантирует сохранность данных пользователей при перезапусках и пересборках контейнера.

## 🤖 Как работает бот

Пользовательский сценарий построен на взаимодействии через FSM (машину состояний) и обработку callback-запросов:

```text

          ┌─────────────┴─────────────┐
          ▼                           ▼
[ Новый пользователь ]     [ Пользователь есть в БД ]
          │                           │
          ▼                           │
[ Выбор языка: RU / EN ]              │
          │                           │
          ▼                           │
[ Ввод населённого пункта ]           │
          │                           │
          ▼                           │
[ Поиск Open-Meteo Geocoding ]        │
          │                           │
   ┌──────┴──────────────┐            │
   ▼                     ▼            │
[ 1 совпадение ]   [ >1 совпадений ]  │
   │                     │            │
   │               [ Выбор из списка ]│
   │                     │            │
   └──────────┬──────────┘            │
              ▼                       │
    [ Сохранение в SQLite ]           │
              │                       │
              └──────────┬────────────┘
                         ▼
             [ Главное меню выбора дня ]
                         │
        ┌────────────┬───┴────────┬─────────────┐
        ▼            ▼            ▼             ▼
   [ Вчера ]    [ Сегодня ]   [ Завтра ]   [ Послезавтра ]
        │            │            │             │
        └────────────┴─────┬──────┴─────────────┘
                           ▼
              [ Суточный прогноз погоды ]
                           │
             ┌─────────────┴─────────────┐
             ▼                           ▼
     [ 🔄 Обновить ]              [ 🔎 Подробнее ]
                                         │
                                         ▼
                             [ Обзор дня (шаг 3 ч) ]
                                         │
                    ┌────────────┬───────┴────┬────────────┐
                    ▼            ▼            ▼            ▼
               [ 🌙 Ночь ]  [ 🌅 Утро ]  [ ☀️ День ]  [ 🌇 Вечер ]
                    │            │            │            │
                    └────────────┴─────┬──────┴────────────┘
                                       ▼
                       [ Детальный почасовой расклад ]
```

1. **/start и выбор языка**:
   - При первом запуске бота пользователю отправляется клавиатура выбора языка (`🇷🇺 Русский` / `🇬🇧 English`).
   - После выбора языка бот сохраняет выбор и переходит в состояние ожидания ввода города на выбранном языке.
   - Если пользователь уже зарегистрирован, бот загружает его настройки (город и язык) и сразу выводит главное меню с прогнозом.
2. **Ввод и распознавание города/села**:
   - Пользователь вводит произвольный текст (например: `село Константиново, Рязанская область`, `д. Простоквашино`, `пгт Шерегеш`, `London`, `Springfield, USA`).
   - Функция `parse_settlement_query` удаляет приставки поселений и отделяет указание региона.
   - Запрос передаётся в Open-Meteo Geocoding API с проверкой вариантов букв «е» и «ё» и учётом выбранного языка.
   - При наличии нескольких вариантов пользователю отправляется клавиатура со списком мест с указанием региона и страны.
   - После подтверждения Telegram ID, название места, координаты, таймзона и язык сохраняются в SQLite.
3. **Выбор дня**:
   - Пользователь выбирает один из 4 дней: **Вчера**, **Сегодня**, **Завтра**, **Послезавтра**.
   - Дата вычисляется динамически относительно часового пояса выбранного населённого пункта.
4. **Просмотр и детализация**:
   - Сообщение мгновенно редактируется с выводом метеорологической сводки на выбранном языке.
   - Кнопка **«🔎 Подробнее»** переключает сообщение в режим 3-часовой сводки за день (ночь, утро, день, вечер).
   - Кнопки периодов суток (**Ночь**, **Утро**, **День**, **Вечер**) раскрывают каждый отдельный час выбранного 6-часового интервала с подробными параметрами осадков, ветра и облачности.
   - Кнопка **«🔄 Обновить»** принудительно инвалидирует кэш и загружает актуальные данные.
   - Кнопка **«📍 Сменить город / село»** позволяет в любой момент задать новую локацию.
   - Кнопка **«🌐 Язык / Language»** (или команда `/lang` / `/language`) позволяет сменить язык интерфейса.

## 🌐 Используемые API

Проект использует три сервиса платформы **[Open-Meteo](https://open-meteo.com/)**:

1. **Geocoding API** (`https://geocoding-api.open-meteo.com/v1/search`)
   - **Назначение**: преобразование текстового названия населённого пункта в географические координаты (`latitude`, `longitude`), определение страны, региона (`admin1`) и часового пояса (`timezone`).
   - **Параметры**: `name`, `count=10`, `language` (`ru` или `en`), `format=json`.
2. **Weather Forecast API** (`https://api.open-meteo.com/v1/forecast`)
   - **Назначение**: получение почасового прогноза погоды на сегодня, завтра и послезавтра (до 7 дней вперёд).
   - **Параметры**: координаты, `timezone`, `forecast_days=7`, `hourly` (`temperature_2m`, `apparent_temperature`, `precipitation_probability`, `precipitation`, `weather_code`, `cloud_cover`, `wind_speed_10m`, `wind_direction_10m`).
3. **Historical Archive API** (`https://archive-api.open-meteo.com/v1/archive`)
   - **Назначение**: получение точных архивных фактических данных погоды за прошедшие сутки (режим «Вчера»).
   - **Параметры**: координаты, `start_date`, `end_date`, `timezone`, `hourly`.

> ℹ️ **Аутентификация и ключи API**:
> Для работы с Open-Meteo API в рамках проекта **не требуется API-ключ** (API Key). Сервисы доступны публично и бесплатно для некоммерческого использования при соблюдении условий открытого использования сервиса.

## ⚡ Кэширование

Для снижения сетевой нагрузки на внешние API и обеспечения мгновенного отклика бота в модуле `app/services/weather.py` реализовано кэширование:

- **Механизм**: in-memory хранилище `_WEATHER_CACHE` на базе структуры данных словаря Python.
- **Ключ кэша**: `{latitude}_{longitude}_{date_str}_{is_archive}`, где учитываются географические координаты, дата и признак архивного запроса.
- **TTL (время жизни кэша)**: **300 секунд (5 минут)**. Повторные нажатия пользователей на кнопки в течение 5 минут обслуживаются без сетевых задержек.
- **Принудительный сброс**: нажатие кнопки `[ 🔄 Обновить ]` в интерфейсе бота передаёт параметр `force_refresh=True`, который удаляет соответствующий ключ из кэша и инициирует свежий HTTP-запрос к API.

## 🗄️ База данных

Проект использует встраиваемую базу данных **SQLite**:

- **Драйвер**: асинхронная библиотека `aiosqlite`.
- **Файл базы данных**: по умолчанию располагается по пути `data/weather_bot.db`.
- **Инициализация**: функция `init_db()` вызывается в функции `main()` при старте бота, создаёт таблицу `users` и выполняет автоматическую миграцию для добавления колонки `language`, если она отсутствует.
- **Схема таблицы `users`**:

```sql
CREATE TABLE IF NOT EXISTS users (
    telegram_id INTEGER PRIMARY KEY,
    city        TEXT,
    latitude    REAL,
    longitude   REAL,
    timezone    TEXT,
    language    TEXT DEFAULT 'ru'
);
```

- **Операции с данными**:
  - `get_user(telegram_id)`: чтение профиля пользователя.
  - `save_user(...)`: вставка или обновление через `INSERT INTO users ... ON CONFLICT(telegram_id) DO UPDATE SET ...`.
  - `set_user_language(telegram_id, language)`: сохранение или обновление выбранного языка интерфейса.
  - `get_user_language(telegram_id)`: получение языка пользователя (по умолчанию `ru`).
- **Поведение в Docker**: папка `/app/data` вынесена в persistent volume `bot_data`, предотвращая потерю данных при остановке или пересоздании контейнера.

## 🧪 Тестирование

Проект покрыт набором из **41 автоматизированного теста**, проверяющих всю бизнес-логику без необходимости отправки реальных сетевых запросов.

### Запуск тестов через `pytest` (рекомендуется)

```bash
python -m pytest
```

### Запуск через встроенный модуль `unittest`

```bash
python scripts/run_tests.py
```

### Структура тестов

- [`tests/test_dates.py`](tests/test_dates.py): корректность загрузки часовых поясов IANA через `zoneinfo`, расчёт относительных дат (`offset: -1, 0, 1, 2`) и названий дней на русском и английском языках.
- [`tests/test_weather_codes.py`](tests/test_weather_codes.py): соответствие кодов Всемирной метеорологической организации (WMO) русскоязычным и англоязычным описаниям и эмодзи, конвертация углов в 16-румбовую розу ветров (`С`, `СВ`, `Ю`, `ЗСЗ` / `N`, `NE`, `S`, `WNW` и др.).
- [`tests/test_formatters.py`](tests/test_formatters.py): компактное форматирование суточной, обзорной и почасовой сводок погоды для экранов 320–375px (строго 1 строка на час/период, моноширинное время `<code>00:00</code>`, округление до целых градусов, устранение дублирования стран и проверка клавиатур на RU/EN).
- [`tests/test_i18n.py`](tests/test_i18n.py): тесты словаря локализации, первого запуска с выбором языка, смены языка интерфейса существующим пользователем и корректности отображения прогнозов на английском языке.
- [`tests/test_geocoding.py`](tests/test_geocoding.py): разбор префиксов типов поселений (`деревня`, `село`, `пгт`, `хутор`, `ст-ца` и др.), выделение региона из круглых/квадратных скобок или запятых, приоритезация населённых пунктов стран СНГ по численности населения, мокированные и интеграционные тесты геокодинга с поддержкой `ru`/`en`.
- [`tests/test_handlers.py`](tests/test_handlers.py): тестирование команд `/start` и `/pogoda` (с городом, без города, в личных и групповых чатах), FSM-состояния `CityStates.waiting_for_city`, сохранение пользователя при единственном результате поиска, генерация клавиатуры выбора при нескольких совпадениях, выбор населённого пункта по кнопке и работа обработчика почасового прогноза.

Сервис упакован в компактный Docker-образ на базе официального `python:3.12-slim`.

Файл `docker-compose.yml`:
```yaml
services:
  bot:
    build: .
    container_name: weather_telegram_bot
    restart: unless-stopped
    env_file:
      - .env
    volumes:
      - bot_data:/app/data

  bot_data:
```

| Задача | Команда |

## 👨‍💻 Разработка

### Организация кодовой базы

- **Обработчики сообщений и команд**: `src/app/handlers/start.py` (команда `/start`, машина состояний FSM для ввода и выбора населённого пункта) и `src/app/handlers/callbacks.py` (обработка нажатий инлайн-кнопок дней, периодов суток и принудительного обновления).
- **Инлайн-клавиатуры**: `src/app/keyboards/weather.py` (кнопки дней, периодов, списков найденных поселений и навигации).
- **Интеграция с внешними API**: `src/app/services/geocoding.py` (геокодинг) и `src/app/services/weather.py` (запрос погоды и архивных данных).
- **База данных**: `src/app/database/database.py` (схема SQLite, SQL-запросы).
- **Утилиты и хелперы**: `src/app/utils/formatters.py` (генерация текстов сообщений), `src/app/utils/dates.py` (календарные даты и часовые пояса), `src/app/utils/weather_codes.py` (WMO-коды), `src/app/utils/logger.py` (конфигурация логов).

### Добавление новых возможностей

1. **Новая команда или меню**: добавьте соответствующий хэндлер в `src/app/handlers/` и зарегистрируйте роутер в `src/main.py`.
2. **Новые метеопараметры**: добавьте необходимые поля в параметр `hourly` функций `fetch_weather_data` в `src/app/services/weather.py` и обновите функции вывода в `src/app/utils/formatters.py`.
3. **Новые тесты**: создавайте тестовые функции с префиксом `test_` в каталоге `tests/` и запускайте через `pytest` или `python scripts/run_tests.py`.

## 🔍 Устранение неполадок (Troubleshooting)

- **`BOT_TOKEN не задан в переменной окружения!` при старте**:
  - Убедитесь, что файл `.env` создан в корневой папке проекта (рядом с `main.py`), и значение переменной `BOT_TOKEN` заполнено корректным токеном без лишних пробелов и кавычек.
- **Населённый пункт не найден**:
  - Проверьте написание названия. Попробуйте указать название региона через запятую, например: `Никольское, Вологодская область`.
  - При поиске редких деревень используйте официальное географическое наименование без неформальных сокращений.
- **Ошибка соединения с сервисом погоды (`httpx.HTTPError`)**:
  - Проверьте доступность серверов `open-meteo.com` с вашего сервера/компьютера.
  - Подробная информация об ошибке и HTTP-статусе автоматически записывается в файл `logs/errors.log`.
- **Проблемы с базой данных в Docker**:
  - Если данные не сохраняются между перезапусками, убедитесь, что в `docker-compose.yml` подключён volume `bot_data:/app/data`, а переменная `DATABASE_PATH` не указывает на несуществующую внешнюю директорию.
